本节以「执行联动」这条核心业务为例，说明应用怎样接收输入、处理数据、判断条件并更新结果，处理流程见图 3.1。

用户在模拟页可以拖动温度、湿度、光照三个滑块，切换「是否有人」开关，也可以点「夏季午休」或「阴雨傍晚」一键套用预置场景。这些操作只改变页面上的四个 @State 变量，此时不发生任何业务计算。

点击「执行联动」后，页面先把四个值组装成一份 EnvData，再调用 RuleEngine.run()。引擎内部按固定顺序处理：先深拷贝设备数组，在副本上推演；再把规则按优先级升序、同级按 id 升序排序；然后逐条求值。求值时先看是否启用、条件与动作是否齐备，再按「且」或「或」判定条件是否成立。不命中或不合格的规则不丢弃，而是连同原因一起记入未执行列表，便于用户理解「为什么这条没生效」。

条件成立后进入动作应用阶段。这是本模块的关键：引擎维护一个从「设备 : 属性」到「首次写入的规则与目标值」的映射。当后续规则对同一组合给出不同目标值时，不覆盖已有值，而是生成一条冲突记录，写明胜者、败者与裁决依据；目标值相同或首次写入时，才真正修改设备并记录一条前后值变化。

执行结束后，页面把 devicesAfter 写回 AppStore，把执行结果追加进日志，再依次调用设备、日志、环境三处持久化。界面上分三块展示结果：按执行顺序编号的触发规则及其命中条件、设备属性的前后变化、以及冲突裁决。用户由此可以完整回答三个问题——哪几条规则被触发了、设备因此变成什么样、有没有规则互相打架。
