宿舍里的电器目前只能逐台手动开关。傍晚回到宿舍，屋里已经暗下来、空气发闷，需要挨个去开灯、开空调、开加湿器；出门上课又常忘记关，空调空转一下午。这些动作本来是有规律可循的：天暗了该开灯，天热了该开空调，空气干了该开加湿器。本项目要做的，就是把「什么条件下该做什么」交给应用自己判断和执行。

用户面对的是一组自动化规则。一条规则由三部分构成：触发条件（如「温度 > 28℃」）、设备动作（如「空调 开」）和优先级。用户可以新建、修改、启用或停用规则，也可以给一条规则配两个条件，并选择两者之间是「同时满足」还是「任一满足」。应用内置照明灯、空调、加湿器、窗帘四类可控设备，以及温度、湿度、光照、是否有人四项环境输入。

智能家居类应用最大的门槛是「看不见效果」——不接真实硬件，用户无法确认规则写得对不对。本项目因此内置了模拟环境：四项环境数据都可用滑块和开关调整，也可一键套用「夏季午休」「阴雨傍晚」两组预置场景。点击「执行联动」后，应用按规则的实际逻辑算出哪些规则被触发、设备变成什么状态、哪些控制互相冲突，并把整个过程按执行顺序记入日志。用户不必接任何硬件，就能把规则调到符合预期。

整个应用的核心是规则引擎而不是界面。因此本项目把引擎做成不依赖任何界面与存储 API 的纯逻辑模块，界面只负责收集输入、展示结果。这样既保证了「同样的环境输入一定得到同样的执行结果」，也让核心业务逻辑能被单元测试独立验证——本项目 12 条自动化测试能够脱离设备直接运行，正是这个分层设计的结果。
