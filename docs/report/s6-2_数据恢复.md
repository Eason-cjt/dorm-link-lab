选取「规则」这一类业务数据说明持久化与恢复过程。规则在使用中会产生三种修改：新增、修改内容、启停。三者走同一条路径：AppStore 修改内存数组后调用 StorageService.saveRules()，后者把整个数组 JSON 序列化后写入 Preferences 的 rules 键并立即 flush。

实测步骤：在规则页新建一条规则「测试恢复」，条件设为湿度 > 80，动作为加湿器关闭，优先级设为 3；保存后返回列表确认该规则存在；随后在系统任务管理器中把应用进程划掉；重新启动应用，进入规则页，该规则仍在列表中，条件、动作与优先级均与保存前一致。用同样的方式验证了其余三类数据：设备状态（空调的开启状态在重启后保持）、环境参数（滑块位置恢复到上次设定）、执行日志（历史记录仍在，可正常展开）。

这里有一个实现细节值得说明。Preferences 单个 value 有长度上限（约 8KB），而执行日志的完整结构包含设备快照，条数一多就会超限，写入直接失败且不抛出明显错误。解决方式是保存前做两步裁剪：只保留最近 8 条，并把体积最大的 devicesAfter 字段清空——设备快照在一次演练结束后已经写回设备状态本身，日志里不需要重复保存一份。
